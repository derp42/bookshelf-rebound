Scope: every result returned by the GitHub Search API for
`repo:bookshelf/bookshelf is:issue is:open created:2017-01-01..2018-12-31`.

were excluded by `is:issue`.

## Method and decision vocabulary

The review covered each issue body and all available comments, GitHub timeline
cross-references where present, Bookshelf release history, the current Rebound
source and tests at `002ab8f`, and relevant behavior in the installed Knex
2.5.1. Small read-only SQLite/SQL-compiler checks were also run. Those checks
confirmed that null filtering (#1540) and `Collection.load()` (#1922) work now,
and reproduced the nested-relation corruption in #1844. A historical issue is
not marked fixed merely because it is old.

Priorities mean: **P0** security or data-loss hazard; **P1** correctness or a
common operational hazard; **P2** compatibility, performance, or worthwhile
enhancement; **P3** documentation/support; **P4** stale, unsupported, or
out-of-scope. Dispositions mean: **FIX** change existing behavior; **ADD** add a
feature, validation, test, or documentation; **VERIFY** first obtain a current
reproduction; **ALREADY_FIXED** current behavior/release history resolves the
report; **DUPLICATE** consolidate under the referenced issue; **REJECT** do not
change Rebound for the request as stated.

`REJECT` does not necessarily mean the reporter's need is invalid. It means the
safe or compatible answer is application code, Knex, a database/schema change,
or documentation rather than a Rebound core change.

## Highest-priority conclusions

- **P0 / REJECT:** #1843 attempts to bundle a direct MySQL connection and its
  credentials into a browser application. Supporting that architecture would
  expose database access to clients. Bookshelf/Rebound and Knex database
  connections must remain server-side.
- **P1 / FIX:** #1844 is still reproducible. A model obtained through a nested
  eager relation has empty `relatedData.parentAttributes`; `refresh()` then
  adds an undefined relation constraint and fails. This needs a regression test
  followed by a narrowly scoped eager-pairing fix.
- **P1 / ADD:** #1571 silently ignores a misspelled `transaction` option, so a
  write intended to be atomic can execute outside its transaction. Add targeted
  option validation without making every options bag globally strict.
- **P1 / ADD:** #1519's `created` event means the INSERT completed, not that the
  surrounding transaction committed. Document and test the boundary; external
  side effects should run only after the outer transaction promise resolves.
- **P1 / ADD:** #1895 needs a safe multi-tenant recipe based on a Bookshelf/model
  factory per Knex instance. Mutating a shared model's connection can route one
  tenant's query through another tenant's connection.
- **P1 / VERIFY:** #1495 demonstrates JavaScript precision loss for a MySQL
  `BIGINT` foreign key. Verify current driver configurations and add a
  relationship regression test before choosing between code and explicit
  `supportBigNumbers`/`bigNumberStrings` guidance.
